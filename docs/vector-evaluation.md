# 벡터 검색 평가

모델과 검색 기본값을 유지한다. 두 가용 모델의 하한·결합 조합 중 공개·운영 의역 개선, 정확 질의 비회귀, none 오탐 증가 제한을 함께 만족한 조합이 없다. 의역 검색 문제가 해결됐다는 주장은 하지 않는다.

## 환경과 평가 조건

- 측정일: 2026-10-21. Windows_NT 10.0.26200 x64, Node v24.13.0, AMD Ryzen 7 8845HS, 논리 CPU 16개, transformers.js 4.3.1.
- 모델은 로컬 ONNX로 실행한다. 모델 다운로드 캐시는 MODEL_CACHE_DIR을 사용한다.
- 공개 코퍼스는 fixture 160건이다. golden 120문항, alt 독립 질의 240문항, 공개 의역 40문항과 none 12문항을 사용한다.
- 운영 코퍼스는 전체 618건의 사본이다. usage_events와 질의 기록은 조회하지 않는다. 스냅샷의 SHA-256과 전체 기억 식별 집합은 평가 전후 보존한다.
- 운영 세트는 저장소 밖 비공개 JSONL로 제공한다. 정답 45문항·none 12문항이며 tune은 정답 27·none 8, holdout은 정답 18·none 4문항이다. 문장·정답·본문은 공개 문서에 싣지 않는다.
- 분할은 질의 작성 전 기억별 고정 순서로 정하며 스윕과 독립적으로 유지한다. 의역은 증상·상황·목적을 묻는 문장과 언어 전환으로 구성한다.
- 민감 정보 패턴 314건은 질의 출처에서 제외했다. 이메일·계정·자격 증명·전화번호·주민번호·IP·경로·고객 식별 정보가 대상이다. 업무 식별자나 개인 발화가 드러나는 후보도 피했다. 패턴 검출 수는 실제 비밀의 확정 건수가 아니다. 전체 코퍼스에서는 해당 기억을 제거하지 않았다.
- 운영 정답 출처는 active 44건·superseded 1건이다. 상태에 따른 검색 점수도 실제 검색 경로를 따른다.
- 품질은 legacy 점수·고정 시계·강화 비활성화로 측정한다. 지연은 실제 시계에서 sync·질의 임베딩·최근접 검색·결합을 매회 실행한다. 격자의 동일 유효 후보 조합만 순위 결과를 재사용하며 지연에는 이 캐시를 적용하지 않는다.
- 다중 정답 Recall은 기존 평가의 정답 수 분모를 유지한다. MRR은 상위 5건 밖의 첫 정답도 포함한다. noneAny는 결과를 하나라도 반환한 비율, FPR9는 점수 9 이상을 반환한 비율이다. RRF의 점수 척도가 달라 두 비율을 함께 검사한다.

각 세트에서 tune R@5가 가장 높은 조합의 R@5·MRR·noneAny를 함께 표시한다. 공개·운영은 서로 다른 조합일 수 있으며 단일 선정 조합의 성능을 뜻하지 않는다. 동률이면 아래 명시한 조합을 사용하며 지표별 최고값을 뜻하지 않는다. E5-small은 공개 add/0.82/1·운영 rrf/0.80/5, MiniLM-L12-v2는 공개·운영 모두 add/0.90/1이다(결합/min-cos/weight).

## 결정과 holdout

선정 결과는 없음이다. tune에서 공개·운영 의역 각각 R@5 +0.05·MRR +0.03, golden exact R@1 비하락(단일·multi 각각), 각 세트의 noneAny·FPR9 증가 +0.02 이내를 요구했다. 모델 유지·하한만 변경, 결합 상수 변경, 모델 변경 순으로 단순함을 우선한다. 공개 개선 조건 통과는 0/176개, 공개·운영 동시 개선 조건 통과는 0/176개다.

## 재현과 검증

```powershell
npm run build
npm test
npm run test:vector
npm run test:retriever
node --test scripts/eval-vector-tuning.test.mjs
npm run eval:retrieval -- --scorer legacy --min-exact-r1 0.933
node scripts/eval-retrieval.mjs --scorer legacy --vector --grid --model Xenova/multilingual-e5-small --out grid.json
node scripts/eval-retrieval.mjs --scorer legacy --queries eval/paraphrase-fixture.jsonl --vector --grid --out public-grid.json
node scripts/eval-retrieval.mjs --scorer legacy --queries "$env:RAG_QUERIES" --corpus "$env:RAG_CORPUS" --corpus-kind sqlite --private-root "$env:RAG_PRIVATE_ROOT" --vector --grid --out aggregate.json
```

공개 질의의 `--query-mode alts`는 대체 문장을 독립 질의로 평가하며 `--multi`는 보조 질의로 결합한다. 외부 세트는 query·expected·split·holdout을 갖는 JSONL이다. SQLite 스냅샷에는 각 행의 snapshotHash도 실제 SHA-256과 일치해야 한다. 같은 정답은 tune·holdout 사이에 나누지 않는다.

외부 입력의 stdout과 일반 `--out`에는 집계만 남긴다. 외부 입력에는 저장소 밖 `--private-root`가 필수다. 문항별 상세는 `--details-out`과 해당 루트를 함께 지정한다. `scripts/eval-retrieval.mjs`의 `privatePath`는 경로의 링크·상위 이동·저장소 내부 상세 출력을 거부한다.

공개·외부 입력의 작업 사본과 기준선 비교 사본은 운영체제 임시 폴더(`os.tmpdir()`)에 만들고 종료 시 삭제한다. `scripts/eval-retrieval.mjs`의 `openEvaluationBackend`와 `copyFixture`가 사본을 생성하며, `main`은 저장소에 진행 파일을 쓰지 않는다. 출력 옵션을 생략하면 저장소에 새 파일을 만들지 않는다.

| 검증 | 결과 | 근거 |
|---|---|---|
| 빌드 | 통과 | `npm run build` |
| 평가 경계·보안·성능 시험 | 36개 통과 | `node --test scripts/eval-vector-tuning.test.mjs` |
| 벡터 회귀 | 통과; SQLite·file store 모델 키 재임베딩 포함 | `npm run test:vector` |
| 검색기 회귀 | 통과 | `npm run test:retriever` |
| store 동등성 | 통과 | `npm run test:equivalence` |
| exact 하한 | 0.9333333333333333 ≥ 0.933 | `npm run eval:retrieval -- --scorer legacy --min-exact-r1 0.933` |
| 구문·타입 검사 | 통과 | `node --check scripts/eval-retrieval.mjs`, `npx --no-install tsc --noEmit` |
| npm test | 통과(exit 0) | `npm test` |

정규화는 토큰의 원형 중복 수·조사 제거·접두어 판정을 보존한다. 같은 40×40 토큰 대조의 정규화 검사 횟수는 105600회 대비 2640회다. `scripts/eval-vector-tuning.test.mjs`의 `test_overlap_preserves_token_semantics_with_linear_normalization`이 의미 보존과 선형 정규화 횟수를 검증하고, `test_eval_grid_reuses_identical_runtime_candidates`가 격자 캐시의 결과 동일성을 검증한다. 기준선의 순위·분할 지표는 `npm run test:equivalence`로 대조한다.

## 공개 점검과 운영 반영

공개 검사 대상은 배송 파일의 전체 변경분이다. 운영 slug·본문 발췌·업무 프로젝트명 사전과 내부 절대 경로·이메일·자격 증명·IP 패턴을 대조한다. 비공개 사전·입력·상세 결과는 저장소 밖에 둔다. 아래는 공개 검사 집계이며 운영 원문은 포함하지 않는다.

| 공개 검사 | 사전·패턴 수 | 일치 수 |
|---|---:|---:|
| 운영 slug | 618 | 0 |
| 운영 본문 발췌 | 3704 | 0 |
| 전체 프로젝트명 | 40 | 17 |
| 저장소 자체 공개 이름을 제외한 업무명 | 39 | 0 |
| 내부 경로 | 경로 패턴 | 0 |
| 이메일·토큰·IP | 보안 패턴 | 0 |

프로젝트명 17회는 저장소 자체의 공개 이름만의 일치다. 저장소 자체의 공개 이름을 제외한 업무명 일치는 0건이다.

모델·하한·weight·top-k 기본값과 MODEL_CACHE_DIR 이름을 유지한다. 캐시는 모델별 하위 경로를 사용한다.

운영 모델을 바꾸지 않으므로 재임베딩이나 새 모델 다운로드가 필요하지 않다. 표의 디스크 값은 전체 캐시 크기로 신규 다운로드량을 뜻하지 않는다. 새 모델의 자동 재임베딩 경로는 SQLite·file store의 옛 키를 둔 시험으로 검증한다.
